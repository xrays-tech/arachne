    2. server::Arachne —— 嵌入 facade

    Arachne::start(ClusterConfig) 是唯一入口：Arachne 是分布式引擎， 单节点也以 ClusterConfig::single_node（N=1 集群）表达，真实集群用 ClusterConfig::member。每进程至多一个节点：静态槽为空时返回 NotInitialized，重复 start 返回 AlreadyInitialized。除 start 与 shutdown 外均为 async。模块同时重导出 ArachneError、Handle、WalConfig。

    pub fn start(config: ClusterConfig) -> Result<Arachne, ArachneError> 同步

    唯一入口，按 ClusterConfig 引导节点：single_node 为 N=1 集群（peerless，自选主、免仲裁轮），member 加入真实集群（tonic 传输，专用多线程 runtime）。data_dir 按需创建；WAL 数据目录锁被获取并持有到节点生命周期结束。第二次调用返回 ArachneError::AlreadyInitialized。

    pub async fn set(key: &[u8], value: &[u8]) -> Result<(), ArachneError> async

    提议一个线性化写（单节点上没有仲裁轮，因此很快）。

    pub async fn get(key: &[u8]) -> Result<Option<Vec<u8>>, ArachneError> asyncReadIndex

    线性化点读。需要 leader：仅在节点自选完成后服务（选主前返回 NotLeader / QuorumUnavailable，调用方轮询至 Ok）。

    pub async fn get_stale(key: &[u8]) -> Result<Option<Vec<u8>>, ArachneError> async本地读

    本地（弱）读：直接读节点自身提交状态；在单节点上即使 ReadIndex 轮未完成也可用。

    滞后读取：写入提交后本节点状态机在毫秒级（实测 ≤7ms）内追平；因此提交后紧接的一次 get_stale 可能返回 None/旧值——单次 None 不是该 key「不存在」的权威否证。需要权威读请用线性一致的 get。

    pub async fn get_stale_with_index(key: &[u8]) -> Result<Option<(Vec<u8>, u64)>, ArachneError> async本地读index ≥1

    本地（弱）读 + value 的溯源序号（v0.3.0）：返回 (value, index)，其中 index 是写入该 value 的那条 log entry 的序号（同 raft 组内跨 key/节点可比、per-key 单调、present 时 ≥ 1；缺键回 None）。

    成本与可用性与 get_stale 相同（本地读、无仲裁、无额外 RTT）——但 value 与其序号同源可证，外部调用方可直接排序而不依赖线性读。滞后读取的注意点与 get_stale 相同（N1：值仍可能陈旧；公开 API 永不出现 index 0）。

    pub async fn delete(key: &[u8]) -> Result<(), ArachneError> async

    删除一个键（提议一个空值）。

    pub async fn handle() -> Result<Handle, ArachneError> async转义出口

    返回本地 Handle 的一个克隆，让嵌入代码能使用完整客户端 API（读、提议、成员变更……）。克隆廉价（共享 actor 通道），节点必须已初始化。

    pub fn shutdown() -> Result<(), ArachneError> 同步

    把状态移出静态槽（先释放 facade 锁再 join，因为 join 会阻塞到 actor 丢弃 WAL 数据目录锁），随后停止并 join actor 线程。无可关闭对象时返回 NotInitialized；第二次调用仍返回 NotInitialized。

    i

    start 返回的 Arachne 是零字段标记：丢弃它是空操作（节点不会因此关闭）， 与显式 shutdown() 刻意区分。

    3. client::Handle —— 全客户端 API

    Handle 是连接一个节点运行时 actor 的客户端入口，Clone 廉价 （包裹 Arc）。一次操作返回 NotLeader 时按提示重定向， 最多 MAX_REDIRECTS（3）次，总 deadline 为一个选举超时，超时返回 Timeout。重定向目标优先 register_peer 注册的进程内对端； 否则（真实多进程集群的任意节点读写）会经 tonic 向提示的 SocketAddr 发送 Forward RPC，由 leader 注入本地运行时完成命令——库内透明转发， 调用方无需自行重发。正常情况下通过 Runtime::new 的返回值或 Arachne::handle() 获得。

    读写操作（async）

    方法（签名）语义
    put(&self, key: &[u8], value: &[u8]) -> Result<(), ArachneError> 线性化写。提议前按 profile 限制校验键/值（fail-stop：非法输入绝无机会进日志），然后等待提交 + 应用（有界 → Timeout）。
    delete(&self, key: &[u8]) -> Result<(), ArachneError> 线性化删除，语义同 put。
    get(&self, key: &[u8]) -> Result<Option<Vec<u8>>, ArachneError> 线性化读。ReadIndex：重定向到当前 leader，leader 以一轮仲裁心跳确认仍居主导后，在读索引应用后服务。不依赖 lease 或时钟漂移。
    get_stale(&self, key: &[u8]) -> Result<Option<Vec<u8>>, ArachneError> 任意陈旧读：直接读本节点已应用状态机。任何节点可答（无重定向），可能陈旧，且不保证单调。滞后读取：写入提交后本节点状态机在毫秒级（实测 ≤7ms）内追平；提交后紧接的一次可能返回 None/旧值——单次 None 不是该 key「不存在」的权威否证，需要权威读请用 get。
    get_stale_with_index(&self, key: &[u8]) -> Result<Option<(Vec<u8>, u64)>, ArachneError> 任意陈旧读 + value 的溯源序号（v0.3.0）：返回 (value, index)，index 为写入该 value 的 log entry 序号（同等 get_stale 的陈旧/非单调语义 N1，但值-序同源可排序；present 时 index ≥ 1，缺键回 None）。

    成员操作（async）

    方法（签名）语义
    add_learner(&self, node_id: RaftId) -> Result<(), ArachneError> 把 node_id 作为 learner 加入（收日志但不投票，不影响仲裁）。提升是单独的显式步骤。
    promote_learner(&self, node_id: RaftId) -> Result<(), ArachneError> 把已追平的 learner 提升为投票成员；落后或失联时返回 LearnerNotCaughtUp。
    remove_member(&self, node_id: RaftId) -> Result<(), ArachneError> 移除成员。移除当前 leader 会自动先移交领导权，再由新 leader 提出移除；移除失败时没有提出任何东西。
    membership(&self) -> Result<(Vec<RaftId>, Vec<RaftId>), ArachneError> 返回已应用的成员关系 (voters, learners)（同为 RaftId 编号）。本地态读取：任何节点（含非 leader）都能答，仲裁丢失时也不会挂起。
    transfer_leader(&self, node_id: RaftId) -> Result<(), ArachneError> 把领导权移交给 node_id；在领导权真正移动（而非 raft 接受请求）后才返回。
    i

    上述成员变更方法（add_learner / promote_learner / remove_member / transfer_leader）的参数 id 是 RaftId（u64）= 成员在 initial_cluster 中的 1 基序号 （initial_cluster 第 i 个成员 ⇒ raft id = i+1，如 n1,n2,n3 三节点 ⇒ 1,2,3）。

    成员变更的单发纪律：同一时刻至多一个成员变更在进行，第二个被 ConfChangePending 拒绝；普通写不受影响。

    重定向与元信息

    方法 / 常量语义
    without_redirect(&self) -> Handle 返回一个单发克隆：跳过整个重定向策略，原样返回 NotLeader{hint}。参考节点 HTTP 面用它把 leader 提示透传给外部调用者。
    register_peer(&self, peer: Handle) 注册一个进程内对端 handle，启用向它的客户端侧重定向。等所有 handle 构造完后再为每个对端调用。
    node_id(&self) -> &NodeId 该 handle 绑定的 NodeId。
    leader_hint(&self) -> Option<(NodeId, SocketAddr)>（async） 报告节点当前的 leader 提示：已知 leader 时返回其 (NodeId, SocketAddr)，否则 None（无 leader / 失仲裁）。受操作 deadline 约束。注意：返回的是 leader 的地址身份（NodeId 字符串 + SocketAddr），不是 RaftId；由 leader_hint 反查其 RaftId：按该 NodeId 在 initial_cluster 中的 1 基位置（第 i 位 ⇒ raft id = i+1）。
    const MAX_REDIRECTS: u32 单次操作跟随的最大重定向次数（当前为 3）。

    仅测试（fault-injection 特性）

    !

    以下方法仅在启用 fault-injection 特性时编译，用于会话幂等与路由/门控测试， 不属于正常运行 API，发布构建不含它们。

    方法（签名）用途
    propose_raw(&self, cmd: Vec<u8>, client_id: u64, seq_no: u64) -> Result<(), ArachneError> 在显式会话下提议一条原始状态机命令。put/delete 每次调用都会铸造新的 seq_no，无法复现“重试”这个幂等场景，此方法专供会话 TTL 测试。
    propose_conf_change_raw(&self, change_type: ConfChangeType, node_id: RaftId) -> Result<(), ArachneError> 以低于公开 API 的层级驱动单步成员变更（例如在另一变更进行中时触发一个），走真实重定向循环。

    4. 存储配置：WalConfig / FsyncPolicy / WalOptions

    WalConfig 是 facade（Arachne::start）与底层 WalStorage::open 共用的存储配置：

    字段类型说明
    fsync_policy FsyncPolicy 条目（日志）记录的 fsync 策略。HardState 无论何种策略都总是 fsync（不变式 I1）。
    segment_bytes u64 单个段文件在滚动前的最大字节数。

    FsyncPolicy 有两个变体：

    • FsyncPolicy::Always —— 每次 sync_entries 都执行真实 fsync（默认）。
    • FsyncPolicy::BatchMs(u64) —— 仅当自上次真实 fsync 以来出现新的（未同步）条目时才执行真实 fsync；ms 参数当前是建议性的，sync_entries 仍是同步持久化屏障。

    WalConfig::default() 为 FsyncPolicy::Always + 默认段大小。底层 WalStorage::open 需要的完整选项结构是 WalOptions（教程第 5 / 7 节都有实例）：

    字段类型说明
    cluster_idString集群标识符。
    node_idString节点标识符。
    configWalConfig存储配置。
    created_at_millisu64创建时间戳（自 Unix 纪元毫秒），由调用方提供——存储核心不读系统时钟。
    fsync_observerOption<Arc<dyn FsyncObserver>>可选观察者：每次段真实 fsync 后被通知。默认 None（零开销）。

    5. ArachneError —— 全部 16 个变体

    每个客户端操作（put / delete / get / get_stale）都解析为一个值或其中一种错误。下表按用途分组，附真实 Display 文案与参考节点 HTTP 面映射。

    变体出现时机HTTP 映射
    NotLeader { leader_hint: Option<(NodeId, SocketAddr)> }本节点不是 leader；提示（可能过期）指向当前 leader。客户端应重定向。提示同样是 leader 的地址身份（NodeId + SocketAddr），不是 RaftId：反查 RaftId 按 initial_cluster 位置（第 i 位 ⇒ raft id = i+1）。409 Conflict + leader body
    QuorumUnavailable失去仲裁：leader 退位、无已知 leader，或 ReadIndex 仲裁轮失败。503 Service Unavailable
    Timeout有界等待耗尽，结果未知（写可能已落）。503
    Busy背压：提议队列或读等待队列满。非致命，稍后重试。503
    InvalidArgument(String)键/值超限等。提议前拒绝，绝不进日志。400 Bad Request
    SessionExpired会话过期或缓存结果被逐出，结果未知。—
    SessionTableFull会话表满，拒绝新会话（已有会话不受影响）。—
    ConfChangePending已有成员变更在飞行（单步 ConfChange 纪律）。重试同一请求即可。409 Conflict
    LeaderRemovalRequiresTransfer移除当前 leader 需要先移交领导权，未获授权。409 Conflict
    LearnerNotCaughtUp { behind: u64, threshold: u64 }learner 落后超过 threshold 或从未应答，提升被拒（防不完整日志入仲裁）。412 Precondition Failed
    ClusterIdMismatch传输握手时对端 cluster_id 不匹配。—
    ShuttingDown节点正在关闭。503
    DataDirLocked数据目录被另一进程锁定。—
    Unrecoverable(String)致命条件（存储损坏、状态机不变式被破坏……）。进程应 fail-stop。500 Internal Server Error
    AlreadyInitialized本进程内 facade 已被初始化，礼貌拒绝第二个 Arachne::start。—
    NotInitialized在 start 前或 shutdown 后调用 facade 静态方法。—
    i

    以 SessionTableFull / SessionExpired 开头的若干变体标注为 “M3” 里程碑的能力；现在的运行路径尚未产生它们，但变体列表已完整保留。

    6. HTTP 接口（arachne-node）

    参考节点把 KV 读写、成员管理与运维探测暴露为纯 HTTP；值从路径取用（URL 安全的 ASCII，body 解析尚未实现）。

    方法与路径含义
    PUT /kv/<key>/<value>在 key 下写入 value（线性化）。
    DELETE /kv/<key>删除 key（线性化）。
    GET /kv/<key>经 ReadIndex 的线性化读。
    GET /kv/<key>?stale=1陈旧读（本地状态机，任何节点可答）。
    GET /members当前成员关系，如 voters=1,2,3 learners=4（本地态，任何节点可答）。
    POST /members/add-learner/<id>添加一个 learner。
    POST /members/promote/<id>提升一个已追平的 learner。
    POST /members/remove/<id>移除一个成员（leader 先移交领导权）。
    POST /members/transfer-leader/<id>移交领导权。
    GET /readyz就绪探测（ready / not ready）。
    GET /metricsPrometheus 格式计数/计量（raft、WAL、read-index）。

    错误映射为 HTTP 状态码 + 纯文本 body：

    状态码场景
    409 ConflictNotLeader（body 带 leader=… addr=… 提示，进到 NotLeader 说明请求打到非 leader）/ ConfChangePending / LeaderRemovalRequiresTransfer。
    503 Service UnavailableQuorumUnavailable / Busy / Timeout / ShuttingDown —— 此刻不是服务能力问题，请求不会挂起。
    412 Precondition FailedLearnerNotCaughtUp（请求合法，重试原样无效）。
    400 Bad RequestInvalidArgument，以及路径形态错误（如 PUT /kv/ 没有 key/value）。
    500 Internal Server Error其余未分类的存储/内部错误。

    一次成功的成员变更只在已应用（持久化）后应答，因此 200 之后 读 /members 即可看到新配置。GET /readyz//metrics 之外的 方法会得到 405；未知路径为 404。
